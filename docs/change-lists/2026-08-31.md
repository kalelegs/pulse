# Monday, Aug 31, 2026

Generative UI, end to end: the agent can now answer with a rendered panel as well
as a voice. Shipped as three waves of one feature.

## [1] json-render block library

Details:

```yaml
commit: 'in-progress'
primary changes:
  - 19 domain-neutral blocks under components/json-render/blocks/, each split into a
    React-free <Name>.definition.ts (zod props, LLM-facing description, example) and a
    'use client' <Name>.tsx.
  - lib/json-render/catalog.ts — the React-free contract shared with the model
    (prompt / validate / jsonSchema / zodSchema), importable from tool code.
  - components/json-render/JsonRenderSurface.tsx — the single render entry point.
    Validates before rendering, falls back visibly on unknown block types, and wraps
    everything in an error boundary.
  - Curated 55-name icon set (icons.ts + iconNames.ts) typed as an exhaustive record,
    so an icon name that has no component is a compile error.
  - lib/spec-builders/ — block() / bind() / buildSpec(), prop-checked against each
    block's own zod schema at compile time.
notes:
  - blockDefinitions and blockComponents cannot drift: TBlockComponents is an
    exhaustive mapped type over the definitions map.
```

## [2] Chat message pipeline

Details:

```yaml
commit: 'in-progress'
primary changes:
  - lib/EventProcessor/messageExtractor.tsx — turns the realtime transport stream into
    chat messages, with per-role trackers (assistantTurn / userTurn) and a turn clock.
```

## [3] Weather experience and agent wiring

Details:

```yaml
commit: 'in-progress'
primary changes:
  - lib/weather/ — typed data layer behind a TWeatherProvider interface. Open-Meteo
    (keyless) implements it; the 28-entry WMO code map now resolves to both a human
    label and a TIconName, with day/night variants.
  - lib/spec-builders/weather.ts + weatherParts.ts — the weather card, composed purely
    from generic blocks and built from a TWeatherReport.
  - tools/weather.tsx — fetches, builds the spec, attaches it, and returns one sentence
    for the model to speak.
  - tools/renderUi.tsx — the generic render_ui escape hatch, letting the agent author
    its own spec for anything the typed builders do not cover.
  - tools/index.ts — a tool registry, mirroring the block registry pattern.
  - agents/initial.ts — instructions now teach screen awareness and interpolate
    runContext.context.preferences, which was populated but never used.
decisions:
  - Tools return speech text AND deterministically attach a pre-built spec. The model
    chooses the experience by choosing a tool; the layout is typed TypeScript. For a
    realtime voice agent that is instant, always schema-valid and unhallucinable.
  - render_ui parameters are hand-written, not jsonRenderCatalog.jsonSchema({ strict: true }):
    that conversion cannot expand z.record, so `elements` degenerates to an opaque object.
    elements is a flat array with per-element key; props/on are JSON strings, parsed and
    validated in execute.
  - Instruction budget — jsonRenderCatalog.prompt() is 26,298 chars (~6.7k tokens) and
    teaches a JSONL-patch protocol that does not apply to tool arguments. Replaced with a
    7,118-char (~1.7k token) reference generated from blockDefinitions, carried in
    render_ui's own description. System instructions stay ~1.6 KB.
  - Geocoding is disambiguated deliberately: Open-Meteo ranks by population, which resolved
    "Santa Clara" to Cuba. lib/weather/chooseMatch.ts prefers a US match only when it is
    comparably prominent, so Santa Clara resolves to California while Paris and London stay
    put. An explicit region argument always wins.
fixes:
  - Removed the leftover console.log('weather tool called').
  - attachSpecToMessage(spec) with no id was a no-op from a tool: the pre-tool-call bubble
    is finalised and activeMessage cleared before the function_call item arrives. Verified
    by replaying events.log.json through createMessageExtractor. tools/attachSpec.ts now
    claims the next assistant message and attaches with an explicit id.
```
